## 二、踩到的 6 个坑

### 坑 1 · 页眉每页重复，污染检索

**现象**：同一行在 51 页里出现 51 次，切分后会进入每一个 chunk。

**处理**：统计所有页的行频次，出现在 ≥40% 页面的行判为噪声，剔除。

**效果**：剔除 1 类噪声行。

---

### 坑 2 · 页脚页码抓不到

**现象**：`第 4 页　共 51 页` 也是页脚，但**每页数字不同**，频次统计永远抓不到。

**处理**：加正则 `^第\s*\d+\s*页...`，另外覆盖 `4/51`、`- 4 -` 等常见格式。

**教训**：**频次统计只能抓"完全相同"，抓不到"模式相同"**。这是那个体检脚本的固有局限。

---

### 坑 3 · 表格塌成"一个格子一行"

**现象**：`get_text("text")` 把两列表格提取成：

```
名词
准确含义
计算机网络
若干结点（计算机、交换机、路由器）和连接它们的链路组成的集合
```

行列关系全丢。后续检索命中的是一堆孤立的词，模型拼不出"这个词对应哪个含义"。

**处理**：表格走单独通道 `page.find_tables().extract()`，转成 Markdown 表。

---

### 坑 4 · 中文标点被挪到末尾

**现象**：即使走表格通道，单元格文本仍然是错的：

```
若干结点（计算机 交换机 路由器）和连接它们的链路组成的集合⏎、 、
```

三个顿号全跑到句子末尾。

**原因**：`table.extract()` 直接拼接单元格内的文本片段，而中文标点（`、，。`）在 PDF 里有独立坐标，拼接时按内部顺序走，位置就错了。

**处理**：改用 `page.get_text("text", clip=单元格矩形, sort=True)`，让 PyMuPDF 按坐标重排。

**效果**：

```
若干结点（计算机、交换机、路由器）和连接它们的链路组成的集合
```

**教训**：**同一个库的两个 API，"能提取"和"提取对"是两回事。** 必须肉眼验一遍样本，不能看到有输出就认为成功。

---

### 坑 5 · 表格内容存了两份

**现象**：`text` 字段里混着塌掉的表格内容，`tables` 字段里又有好的那份。41/51 页受影响，重复约 1.7 万字。

**处理**：取正文时用 `get_text("blocks")`，跳过与表格包围盒重叠面积 >50% 的块。

**效果**：正文字符从 45252 → 33819。

**为什么重要**：对 RAG 来说，重复内容会挤占上下文窗口、浪费 token，还可能让检索命中"塌的那一份"。

---

### 坑 6 · 换行处理粒度用错

**现象**：为修表格单元格的 `小 写`，在清洗函数里加了"换行变空格"。结果正文的换行也被吃掉了：

```
1.2　从网络到互联网 1.2.1　三个容易混的名词判断的关键是...
```

标题和正文粘成一句，**结构彻底丢失**。

**处理**：`clean_text(s, flatten: bool)`——表格单元格 `flatten=True` 压成一行，正文 `flatten=False` 保留换行。

**教训**：**清洗函数是全局通用的，但"换行有没有意义"是上下文相关的。** 一个函数服务两种场景，迟早出错。

## 四、已知残留问题（下一步要解决）

**1. 表格被移走后，正文出现"悬空指代"**

第 4 页正文开头是：

```
1.2.1　三个容易混的名词
判断的关键是"协议是否统一为 TCP/IP"：...
```

「判断的关键」指的是上面那张"名词/含义"对照表，但表格已经不在正文里了。

**影响**：单个 chunk 可能缺少它引用的表格，模型答不准。

**下一步**：切分时把表格与相邻正文绑定成同一块，或在表格原位置插入占位符（如 `[表格：名词对照，见 tables/4-1]`）。

**2. 多栏页面（第 9、45 页）未验证**

体检脚本标记了 2 页疑似多栏，但大概率是表格造成的误判。需要人工看一眼确认。

**3. 表格跨页拆分未处理**

69 个表格里如果有跨页的，会被拆成两个独立表格，表头只在第一半有。需要检查。

## 五、这个方法能复用到别的文档吗

能。换一份 PDF，只需要：

```powershell
python scripts/inspect_pdf.py data/新文档.pdf
python -m pipeline.parser data/新文档.pdf data/新文档.jsonl
```

然后看两件事：**正文有没有断句/结构丢失**、**表格 Markdown 有没有错位**。

不同的文档会暴露不同的问题（扫描件要 OCR、多栏要版面分析、双栏论文要分栏切分），但**"先量化、再修、留记录"这个流程不变**。
